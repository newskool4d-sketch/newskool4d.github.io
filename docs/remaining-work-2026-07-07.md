## 0. 고도화 결론

이 프로젝트의 다음 단계는 기능 확장이 아니라 **정본화**다. 현재 이미 만들어진 신형 구조(`unified-map.html` + `js/` 모듈 + 테스트)를 공개 지도의 기준으로 승격하고, 구형 공개 페이지와 문서·배포·데이터 기준을 그쪽으로 맞추는 것이 핵심이다.

### 0-3. 실행 원칙

1. **현재 변경 상태 보존 후 착수**: 미추적 파일이 많으므로 먼저 보존 단위를 확정한다.
2. **검증 가능한 단위로 전진**: 각 단계는 구문검사, 단위테스트, 브라우저 스모크, 문서 갱신 중 하나 이상의 검증을 남긴다.
3. **구형 기능은 목록화 후 이식**: 기능 인벤토리 없이 통합지도 이식에 들어가지 않는다.
4. **공개 범위는 자동화로 지킨다**: 사람이 기억하는 배포 규칙이 아니라 CI와 스크립트가 차단한다.
5. **디자인은 재설계하지 않고 이행한다**: 이미 확정된 `DESIGN.md`를 구현에 맞춘다.

## 3. 개선안 상세

### 3-1. 저장소 구조 개선

현재 사용자가 보는 최상위 폴더와 실제 앱 저장소가 분리되어 있다. 단기적으로는 문서와 명령 예시에서 실제 앱 루트를 명확히 쓰고, 중장기적으로는 구조 평탄화를 검토한다.

권장 순서:

1. 현재 변경분을 먼저 보존한다.
2. 실제 앱 루트를 기준으로 CI와 배포 명령을 정리한다.
3. 구조 평탄화가 필요하면 OneDrive 동기화를 잠시 멈춘 뒤 `git mv` 중심으로 진행한다.
4. 평탄화 후 README, 체크리스트, 배포 문서의 경로를 한 번에 갱신한다.

### 3-2. 검증 체계 개선

현재 테스트 자산은 충분하지만 자동화가 약하다. 수동 체크리스트와 CI를 분리해서 운영하는 편이 좋다.

- 매 변경 시 자동: `node tools/check-syntax.mjs`, `node --test tests/*.test.mjs`, 민감파일 문자열 검사
- 단계 게이트 시 수동: 실제 Kakao JS 키 스모크, 모바일 375px 확인, Chrome/Edge 확인
- 배포 직후 수동: 운영 URL 접속, 지도 타일 렌더링, 마커 클릭, 필터 1회, 키 삭제

### 3-3. 데이터 거버넌스 개선

공개 지도에서 가장 중요한 것은 최신 기능보다 기준일과 출처다. 화면, 데이터, 문서가 같은 기준일을 말하도록 맞춘다.

권장 문구:

> 본 지도는 개인 제작 참고자료로 공식 자료가 아닙니다. 학교 현황은 인천광역시교육청 홈페이지 공개 자료(2026.4.1. 기준)를 준용합니다.

개선 항목:

- `data/schools.json` 또는 별도 메타 파일에 기준일, 출처, 생성 스크립트, 생성일 기록
- `docs/data-update-guide.md`에 갱신 절차와 검수 기준 작성
- 화면 푸터 또는 정보 패널에 동일 고지 표기

### 3-4. 디자인 및 UX 개선

새 디자인을 다시 만드는 것보다 이미 작성된 `DESIGN.md`를 구현 상태와 맞추는 것이 우선이다.

- `index.html`은 마케팅형 랜딩보다 얇은 허브로 축소한다.
- 공개 지도는 `unified-map.html` 중심으로 단일화한다.
- 구형 다크/틸 테마는 재도색보다 통합지도 승격 과정에서 제거한다.
- 색상은 인천교육청 CI에서 파생한 색상 체계를 쓰되, 심벌마크와 로고타입은 사용하지 않는다.
- 모바일 바텀시트, 필터 칩, 지도 툴바는 375px 기준으로 터치 목표 44px 이상을 확인한다.

### 3-5. 보안 및 공개 범위 개선

공개 저장소에는 정적 공개 자산만 올라가야 한다. 비공개 업무용 파일, REST 키, 업무용 CSV는 배포 대상과 저장소 대상에서 분리한다.

개선 항목:

- 공개 배포 파일 화이트리스트 스크립트 작성
- `.gitignore`에 업무용 CSV 패턴 보강
- CI에서 `KAKAO_REST_API_KEY`, `KakaoAK`, 실제 키 패턴, 업무용 파일명 패턴 검사
- `business.html`, `private-local-map.html`은 README에 로컬 전용으로 계속 명시

## 5. 작업 패키지 상세

### 5-1. 패키지 A: 기준 상태와 경고 제거

- 목적: 후속 변경을 시작할 수 있는 깨끗한 기준선을 만든다.
- 주요 파일: `package.json`, `pre-deploy-checklist.md`, `README.md`, 본 문서
- 포함 작업: 작업 트리 분류, 실행 루트 통일, Node 모듈 경고 제거, 죽은 QA 경로 제거
- 검증: `node tools/check-syntax.mjs`, `node --test tests/*.test.mjs`
- 완료 기준: 구문검사와 단위테스트가 경고 없이 통과하고, 문서의 실행 명령이 실제 파일을 참조한다.

### 5-2. 패키지 B: 데이터 신뢰성

- 목적: 공개 지도에서 “언제, 어디 자료를 기준으로 했는지”를 명확히 한다.
- 주요 파일: 공개 HTML 4종, `data/schools.json`, `docs/data-update-guide.md`, README
- 포함 작업: 고지 3종 표기, 데이터 메타데이터 정리, 갱신 절차서 작성
- 검증: 화면 수동 확인, 데이터 기준일 grep, 절차서 재현성 검토
- 완료 기준: 화면·데이터·문서가 같은 기준일과 출처를 말한다.

### 5-3. 패키지 C: 안전한 배포

- 목적: 민감 파일과 키가 공개 배포에 섞이는 일을 자동으로 막는다.
- 주요 파일: `.github/workflows/`, `.gitignore`, README, 배포 스크립트 또는 체크리스트
- 포함 작업: CI, 민감파일 grep, 공개 파일 화이트리스트, 배포 전 체크리스트 갱신
- 검증: 정상 케이스 녹색, 의도적 키 문자열 또는 CSV 패턴 삽입 시 실패
- 완료 기준: 사람이 기억하지 않아도 공개 범위 위반이 차단된다.

### 5-4. 패키지 D: 통합지도 정본화

- 목적: 신형 지도 구조를 실서비스 정본으로 승격한다.
- 주요 파일: `unified-map.html`, `js/`, `shared.js`, `schools.html`, `infrastructure.html`
- 포함 작업: 기능 인벤토리, 프리셋 URL, 베타 노출, 구형 기능 이식, 구형 URL 스텁
- 검증: 단위테스트, fake Kakao 브라우저 QA, 실 키 스모크
- 완료 기준: 기존 공개 페이지 사용자가 기능 손실 없이 통합지도 경로로 이동한다.

### 5-5. 패키지 E: 디자인·접근성 이행

- 목적: `DESIGN.md`의 설계가 실제 화면에 반영되게 한다.
- 주요 파일: `DESIGN.md`, `shared.css`, `index.html`, `unified-map.html`
- 포함 작업: 토큰 교체, 다크/틸 잔재 제거, index 허브화, 모바일·접근성 QA
- 검증: 폐기 토큰 grep, 375px/768px/1280px 확인, 키보드 이동, 대비 점검
- 완료 기준: 디자인 시스템 체크리스트와 접근성 체크리스트가 실제 화면 기준으로 완료된다.

## 8. 완료 기준

후속 고도화는 아래 조건을 모두 만족할 때 1차 완료로 본다.

- 공개 페이지에 비공식 고지, 기준일, 출처가 일관되게 표시된다.
- `node tools/check-syntax.mjs`와 `node --test tests/*.test.mjs`가 경고 없이 통과한다.
- CI가 구문, 테스트, 민감파일 게이트를 자동 실행한다.
- 실 Kakao JavaScript 키로 지도 타일, 마커 클릭, 필터 동작을 1회 이상 확인했다.
- `unified-map.html`이 공개 지도 정본이 되고, 구형 공개 페이지는 리다이렉트 또는 제거 상태가 된다.
- DESIGN.md 체크리스트와 접근성 체크리스트가 문서상 완료 처리되어 있다.
- 데이터 갱신 절차서와 연 2회 갱신 기록 체계가 존재한다.
- 배포 전후 검증 근거가 릴리스 단위로 보존되어 있다.
